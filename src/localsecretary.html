Local Secretary

自分のPCの上で動くLLMを中核に、生活と学業の情報をひとつにまとめる「自分専用のAI秘書」です。データをクラウドに出さず、頼まれなくても動き、これからの予定とリスクを見張り続ける仕組みを作っています。

  • 状態作成中（基盤は稼働中／秘書機能は設計完了・実装フェーズ）
  • 動く場所ノートPC 1台（Intel Core Ultra 5 228V・Arc内蔵GPU・32GB共有メモリ）
  • 中核モデルQwen3.8-27B（OpenVINO Model Server）
  • データの置き場所すべてローカル（Obsidian の Markdown）

01概要

ノートPC（Intel Core Ultra 5 228V、Intel Arc 内蔵GPU、32GB 共有メモリ）の上で、27B クラスの LLM を常時稼働させ、それを「秘書」として育てる個人プロジェクトです。

チャットボットとして使うのではなく、次のような動きをする秘書を目指しています。

  • 講義・メール・予定などの情報を自動で集約する
  • 約束や締切を台帳に置き、「閉じるまで」追跡する
  • 出席率や期限の軌道を予測して、悪化する前に警告する
  • 夜間にまとめて処理と記憶の整理を行う

すべての処理をローカルで完結させ、学業や生活のデータを外部サービスに送らないことが設計の大前提です。

02できていること

基盤の部分はすでに毎日動いています。秘書としての機能は、ここに積み上げていく段階です。

ローカルAI基盤

OpenVINO Model Server で Qwen3.8-27B を常時稼働させています。自動起動、5分間隔の死活監視と自動復旧、1日1回の予防的再起動まで含めて運用しています。

用途別のモード切替

Qwen（AI秘書）／LM Studio（講義処理）／全部ストップ を、共有GPUメモリの競合なく切り替える運用基盤を作りました。

講義パイプライン

講義の録音を投入すると、自動で文字起こしと要約を行い、Obsidian のノートを生成する仕組みが動いています。

つながっているもの

MMU BeeBoard、カレンダー、GitHub、そしてこのポートフォリオサイト。日々の情報が集まる入り口はすでに用意してあります。

03これからやっていくこと

  1. 秘書の台帳と記憶の構築。Obsidian 上に予定・約束・長期記憶の状態ファイル群を作り、秘書が読み書きする土台を整えます。
  2. 能動エンジン。朝の点検、夜間の突き合わせバッチ、講義ノートからの締切自動抽出など、頼まれなくても動くジョブ群を作ります。
  3. 未来レーダー。出席率（80%を割る予測）や締切の衝突を先回りで検知し、逆算して準備タスクを仕込む仕組みです。
  4. メールの自動振り分け。分類・要約・公式メールの平易な解読を自動化し、重要なものだけを前に出します。
  5. 自分専用のプラットフォーム。すべての通知と秘書への指示を一箇所に集約する、スマホ対応のダッシュボードを作ります。
  6. 記憶の育成。日々の記録を週次で統合し、科目ごとの間違い傾向の分析や専用ドリルの生成など、蓄積から生まれる機能へ進みます。

04設計の考え方

ローカルの27Bモデルは、クラウドのモデルと比べると遅く、GPUメモリの余裕もありません。その制約を前提に、無理をさせない構成にしています。

  • 共有GPUメモリの上限（約22GB）と戦う。27Bモデルを安定して常駐させるために、ドライバの更新とメモリ予算の調整、モデル常駐の排他制御を実装しました。
  • 「無言死」を前提にする。推論サーバーがログを残さずに停止する障害を観測し、死活監視・自動復旧・予防的再起動で常時稼働を維持しています。
  • LLMを自律エージェントとして酷使しない。決め打ちのスクリプトが手足、LLMは単発の判断だけ、重い処理は夜間バッチ。この役割分担で設計しています。
  • 正のデータは人間が読める形に置く。データの正は Markdown（Obsidian）に置き、画面やDBはその複製に限定しました。システムが壊れても記憶が残る構成です。
